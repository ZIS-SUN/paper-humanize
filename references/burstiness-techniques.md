## 为什么 burstiness 是降 AIGC 核心

**研究数据**：人类学术写作的句长分布是**双峰**的，σ² 通常在 150-400。
GPT 类 AI 写作的句长分布是**单峰**的，σ² 通常 < 50。

GPTZero、Originality.ai、Turnitin AI 检测器把句长方差作为**第一性指标**之一。维普 / 知网虽然主要看 n-gram 重叠，但其 AIGC 模块也加入了节奏特征。

提升 σ² 是降 AIGC 中**风险最低**的操作（不动内容，不动术语，不动论点），收益却很高。

## σ²_len 计算速查

句长方差 = E[(L - μ)²]，其中 L 是每句字数，μ 是平均字数。

简化估算法（适合人手算）：

- 列出每句字数 [a, b, c, d, e]
- 算平均 μ = (a+b+c+d+e)/5
- 算每句偏差平方 (a-μ)², (b-μ)², ..., 求和
- 除以 5（或 4，看是否做样本/总体校正）

**经验阈值**：

| σ² 区间 | 判断 |
|---|---|
| < 30 | AI 单峰特征极强 |
| 30-80 | AI 单峰特征中等 |
| 80-150 | 偏 AI，但接近健康 |
| 150-400 | 健康双峰（目标区间） |
| 400-800 | 节奏过度，可能拆得太碎 |
| > 800 | 过度极端化，伤可读性 |

## 手法 1：拆 (Split)

### 适用场景

段落里有连续 ≥ 3 句"AI 标准均匀句"（25-35 字）。这是 GPT 输出的典型节奏。

### 拆的"破口"

每个均匀句都有一个**自然拆分点**。常见破口：

1. **逗号转句号**：把"...，并..."改为"...。同时..."（注意：连接词要换，否则又变模板）
2. **从句独立**：把"...，是因为..."改为"...。原因在于..."
3. **并列项分句**：把"包括 X、Y、Z"拆为"包括 X。其中 Y..."（仅当后面要展开 Y 时）
4. **修饰语前置成短句**：把"在 ... 的条件下，本研究 ..." 改为"前提条件如下：...。在此前提下，本研究..."

### 拆出"短-长"组合（核心目标）

不是简单切两半，而是切出**一短一长**：

❌ 平均拆：30 字 → 15 + 15（依然单峰）
✅ 双峰拆：30 字 → 8 + 50（一短一长，但需要补内容）
✅ 双峰拆：30 字 → 10 + 25（接受合并相邻句来达到长句）

### 实例

❌ 改前（5 句，长度 [27, 30, 28, 32, 29]，σ²=2.8）：
> 注意力机制是序列建模的核心组件。它通过加权聚合实现信息选择。在 Transformer 中被广泛采用。后续工作进行了多种改进。本节给出一个统一的形式化描述。

✅ 拆+断后（长度 [11, 28, 56, 18, 7]，σ²=320）：
> 注意力机制是序列建模的核心。它通过加权聚合实现信息选择，在 Transformer 中作为主干被广泛采用。后续工作（如稀疏注意力、线性化注意力、长上下文优化）从计算复杂度、上下文长度、模式表达三个方向进行了改进。本节给出一个统一的形式化描述。三类改进可纳入同一框架。

注：第二句合并了原 §句2 §句3 的并列内容，长句一极由此产生。第五句"三类改进可纳入同一框架"是断句。

## 手法 2：合 (Merge)

### 适用场景

段落里有连续 ≥ 3 句**短碎句**（8-15 字），通常出现在方法描述、实验设置、配置罗列。

### 合的关键：主从层次

**❌ 不要把短句串成"逗号长句"**：

> 实验使用 RTX 3090，batch size 是 32，学习率是 1e-3，epoch 是 50。

这只是逗号串接，没有主从层次，维普依然识别。

**✅ 把次要信息塞进括号 / 嵌套从句 / 定语后置**：

> 实验在单卡 RTX 3090 上训练 50 个 epoch（batch size = 32，初始学习率 1e-3，cosine 衰减）。

主句"实验在 ... 上训练 50 个 epoch"是骨干，括号是细节。

### 三种合并形态

1. **主句 + 括号补充**：把次要信息放括号
   - "本方法采用 Adam 优化器（β₁=0.9, β₂=0.999, ε=1e-8）。"

2. **主句 + 定语后置**：用定语从句修饰主句中的名词
   - "本方法采用 Adam 优化器，其超参数沿用原论文默认值。"

3. **主句 + 介词短语**：用"在 ... 时""通过 ... 实现"等串接
   - "本方法在小样本场景下通过对比学习实现表示对齐。"

## 手法 3：断 (Punch)

### 适用场景

整段都是中等长度句（20-40 字），缺一个极短句来制造峰值。

### 学术断句词库（5-12 字）

**陈述型**（最常用）：

- "结果并非如此。"
- "差异显著。"
- "该假设并不成立。"
- "上述结论存在边界。"
- "前提一旦松动，结论失效。"
- "答案在数据里。"
- "本节证明了三件事。"
- "情况比想象的复杂。"

**限定型**：

- "但仅限于 X 场景。"
- "前提是 Y 成立。"
- "条件依然苛刻。"

**收束型**：

- "证明完毕。"
- "讨论到此。"
- "本节结束。"（很少用，仅章末）

### 插入位置

| 位置 | 用途 | 示例 |
|---|---|---|
| 段首（第 1 句） | 设定基调 / 提出疑问 | "该问题至今未解。然后展开为何未解的论述。" |
| 段中转折点（≈ 中位） | 转换视角 | "...之前认为是 X。但结果并非如此。事实上..." |
| 段尾（最后一句） | 给出收束论断 | "...上述讨论给出了完整证明。三个条件缺一不可。" |

### 断句的禁忌

❌ 不要用感叹号 / 反问 / 诗化（"看那真理！" "难道不是吗？" "答案，在风里"）
❌ 不要用过短的口语断句（"对的。" "没错。" "确实。"）
❌ 不要每段都用断句（一旦每段都用，就变成新的 AI 模板）
❌ 不要在数学证明 / 公式推导段用断句（破坏推导节奏）

## 改写后必须满足

1. **至少 1 个短句 (< 15 字)**
2. **至少 1 个长句 (> 50 字)**
3. **最长句 / 最短句 字数比 ≥ 3:1**
4. **σ²_len ≥ 150**

如果改写后某项不达标，回炉重做或选择合适的手法（差短句就用断、差长句就用合、整体均匀就用拆）。

## 反模式（你不应做的）

❌ **均匀拆短**：把所有句子都改成 10 字短句 → σ² 反而极低
❌ **均匀合长**：把所有句子都改成 60 字长句 → σ² 反而极低
❌ **逗号长句**：用逗号串成"伪长句" → 维普依然识别
❌ **每段断句**：每段都用"...是关键。" → 新的 AI 模板
❌ **凭空补内容**：拆句时加入原段没有的事实 → 越界（那是 Axis-C）
